# S2: Packaging and hosting

Spike S2 ([08 §3](../08-implementation-plan.md#s2--packaging-and-hosting--05-day-after-m1)) asks whether local packages and hosted bundles work well in the browser, at the smallest transfer for acceptable complexity (Q3). It decides how hosted bundles are stored (option A, B, C or D, [04 §9](../04-data-pipeline-and-bundle-format.md#9-compression-and-hosting-spike-s2)) and whether package entries are stored or deflated. Tracked in [#15](https://github.com/jbird/race-replay/issues/15), where the acceptance criteria are.

> **Status:** partly measured. Sizes and the fit to Pages' gzip are done. Still to come: decode times, package opening and memory in the browser (a throwaway page on `spike/s2-browser`), then your laptop rows. The [reading so far](#reading-so-far) holds unless those numbers change it.

## Setup

- **Builds:** `scripts/s2-variants.cs`, a .NET 10 file-based app, run with `dotnet run scripts/s2-variants.cs`. It takes about 70 s.
  - Synthetic seed 1 (Corrie Motor Circuit), 20 cars, built through the real `ReplayBuilder` and `ReplayBundleWriter` onto the 4 Hz timeline.
  - Lap counts come from a linear fit of samples against laps: 265.6 samples per lap plus 626 of overhead.
  - **Stand-in progress:** M2 derives the real channel. Until then, each car's progress is its cumulative distance travelled along its own X/Y, in track units, as Float32. It is monotonic and smooth like the real channel, so it should compress like it.
  - The build time is fixed, so two runs write byte-identical files. The script prints a SHA-256 for every file, and two runs print identical output.
  - Output goes to the gitignored `artifacts/s2/`. Nothing it writes is committed.
- **Variants** of the 2-hour `positions.rrb`, all the same length as the raw file:
  - **raw:** schema 1.0, as written today;
  - **delta:** X and Y as differences from the previous sample, wrapping in 16 bits, with flag bit 0 set (04 §7.3);
  - **delta-qprogress:** as delta, plus progress rounded to whole track units and stored as Int32 differences (a candidate encoding, id 4).

  The script decodes each variant and checks it against the raw file: X and Y exactly, progress within half a track unit, and every header and directory byte except the flags and the changed encodings.
- **Packages:** `.rrz` files with the 04 §7.1 entries (`manifest.json`, `positions.rrb`, `DATA-NOTICE.txt`), written once with stored entries and once deflated (`CompressionLevel.Optimal`). Each is read back with `ZipArchive` and `ReplayBundleReader`. There is no `gaps.rrb` yet.
- **Compressors:**
  - "gzip *n*" with **classic zlib** is GNU gzip 1.14 (`gzip -n -<level>`), used to predict Pages;
  - "gzip *n*" with **zlib-ng** is .NET 10's `GZipStream` with `ZLibCompressionOptions`, which is what the CLI would write for option B or C;
  - Brotli is .NET's `BrotliEncoder`, quality 11, window 22. Pages never sends Brotli, so it is for reference only.

- The generator stops at 200 laps, so the 10 MB build adds a longer cool-down. The cars keep circulating, so the data stays realistic rather than parked cars that compress to nothing.

### Pages' gzip

Checked with `curl` against https://jbird.github.io/race-replay/ on 16 October 2026. Each demo file was fetched twice: without `Accept-Encoding` for the exact deployed bytes, and with `Accept-Encoding: gzip`.

| File | Raw | Pages | Classic gzip 5 | Difference |
|---|---:|---:|---:|---:|
| Seed 1 `positions.rrb` | 1,417,504 | 1,260,855 | 1,263,778 | −0.23 % |
| Seed 3 `positions.rrb` | 1,664,224 | 1,496,555 | 1,500,466 | −0.26 % |
| Seed 7 `positions.rrb` | 1,486,464 | 1,379,031 | 1,378,821 | +0.02 % |
| Seed 1 `manifest.json` | 6,180 | 2,622 | 2,621 | +1 B |
| Seed 3 `manifest.json` | 7,061 | 2,956 | 2,956 | 0 B |
| Seed 7 `manifest.json` | 6,162 | 2,635 | 2,636 | −1 B |

- **Pages behaves like classic zlib at level 5.** The compressible manifests separate the levels best. Level 5 matches all three to a byte, level 4 is about 1 % larger, and levels 6–9 differ by up to 0.25 %. No level is byte-identical, so Pages' compressor isn't exactly GNU gzip, but the sizes agree to within 0.3 %.
- zlib-ng (.NET) fits worse: its closest level is 7 bytes off on the manifests.
- Responses carry `Content-Encoding: gzip` and `Content-Type: application/octet-stream`, from Fastly (`Via: 1.1 varnish`).

So a variant's transfer from Pages is predicted by classic gzip 5, give or take 0.3 %.

### Transfer size of the 2-hour bundle

`positions.rrb`, bytes. The options are those of 04 §9, plus D from #15.

| Variant | Raw | Pages (classic gzip 5): A, D | gzip 9, zlib-ng: B, C | Brotli 11 (reference) |
|---|---:|---:|---:|---:|
| raw | 4,614,464 | **3,973,258** (−14 %) | 3,922,850 (−15 %) | 2,747,764 |
| delta | 4,614,464 | **3,277,438** (−29 %) | 3,227,353 (−30 %) | 2,010,897 |
| delta-qprogress | 4,614,464 | **1,925,879** (−58 %) | 1,770,782 (−62 %) | 1,104,697 |

- **Only quantised progress gets under NFR-04's 3 MB.** Raw (A or B) is about 3.9–4.0 MB over the wire. Delta on X and Y alone is about 3.2–3.3 MB.
- **Pre-gzipping (B, C) gains little over Pages' own gzip:** 1–2 % on raw and delta, 8 % on delta-qprogress. Classic gzip 9 does no better than zlib-ng: 3,972,987, 3,274,837 and 1,788,089 B.
- The manifest adds about 2.6 KB over the wire. `gaps.rrb` is 0.58 MB raw (04 §7.4), so even uncompressed it leaves delta-qprogress under 3 MB.

### Where the bytes are

All cars' blocks of each channel, concatenated in file order, bytes:

| Channel | Raw | gzip 9, raw | gzip 9, delta | gzip 9, delta-qprogress |
|---|---:|---:|---:|---:|
| X | 1,135,480 | 1,058,095 | 631,642 | 631,642 |
| Y | 1,135,480 | 952,934 | 653,028 | 653,028 |
| Progress | 2,270,960 | 1,871,521 | 1,871,521 | **380,505** |
| Validity | 70,980 | 203 | 203 | 203 |

- **Progress is half the file and nearly half the compressed size.** Float32 mantissas barely compress (−18 %). As whole track units, delta-encoded, it shrinks to 0.38 MB, a fifth.
- Delta encoding cuts X and Y by 30–40 % after gzip.
- Rounding progress to a track unit (0.1 m) loses nothing that matters. Float32 already resolves only about 0.5 units at 5,000,000 units, the end of a 2-hour race. At 80 m/s, 0.1 m is 1.25 ms of gap.

## Reading so far

Not decisions yet: decode times and package opening in the browser still have to be measured.

1. **Hosted bundles: option D, with quantised progress.** By #15's rule, the simplest option that meets NFR-04 wins.
   - A and B miss NFR-04 by about 1 MB.
   - D needs only prefix sums at load and no decompression code, and Pages' gzip takes it to 1.93 MB.
   - C is 8 % smaller than D, short of the 15 % that would justify a decompression path.
2. **Format:** delta X/Y and quantised progress look worth putting into the format in M4 (#28–#30), before golden bytes are fixed. Waiting for schema 1.1 would mean shipping demo bundles that miss NFR-04. Progress quantisation does most of the work: 1.35 MB of the 2.05 MB saved over the wire, so it matters more than delta on X/Y.
3. **Packages:** today's format deflates by under 15 %, which points to stored entries. If decision 2 holds, deflating saves about 61 %, and the rule then favours deflating, if it stays under NFR-03's 1 s. The browser timings decide.
